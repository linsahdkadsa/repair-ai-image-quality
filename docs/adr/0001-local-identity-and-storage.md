# ADR-0001：本地身份与持久化基线

- 状态：Accepted for P00 planning baseline；运行实现仍待 P03/P04 验证
- 日期：2026-11-04

## 背景

目标是单机本地图像验证工具，要求真实命名身份、任务与文件持久化、断电/进程恢复，不依赖数据库服务。计划指定 Basic 默认，同时要求生产非 loopback 只能走 HTTPS。

## 决策

1. 默认使用受控命名账号 HTTP Basic；禁止匿名、默认口令或模拟用户作为验收身份。凭据由受控凭据文件或环境变量注入，存储审核过的密码哈希，不入源码、前端、日志或交接证据。缺凭据启动失败。
2. loopback 本机访问可使用 HTTP；任何非 loopback 生产访问要求可信 HTTPS 入口。写操作验证 Origin/同源策略。若已有企业 SSO，只能作为替代身份源，经 P03 验证其真实主体、权限映射、到期/撤销和审计后另行 ADR；不可因此关闭认证。
3. 一个进程独占配置的数据根目录；安装目录与业务数据分开。冲突实例拒绝启动。
4. 首版使用 schemaVersion/version 的 JSON 文档，写临时文件、flush 并在同一文件系统原子替换；乐观锁冲突返回 409。文件以随机/不可枚举 ID 存放在私有目录，API 不接受或返回物理路径。
5. 不引入数据库或 migrations。首版单实例、本地文件对象、有限管理查询；减少运行依赖和部署维护面。并发、查询、完整性若不满足实测要求，先记录指标与 ADR 再改变方案。
6. 凭据文件轮换先完整验证，再原子替换内存凭据快照；下一请求拒绝旧凭据。失败保留旧快照并报告。仅用环境变量时需受控重启才生效，重启前不得声称撤销完成。

## 后果与验证

Basic 必须验证 SSE/下载浏览器凭据行为；跨设备/局域网需 TLS 终止与受信任代理边界。JSON 原子替换不等同于多进程事务，因此独占锁不可省略。P03 覆盖无/错/过期凭据、两账号隔离、锁冲突、权限拒绝、轮换成功/失败；P04 覆盖崩溃恢复和乐观锁；P12 覆盖非 loopback HTTPS、备份恢复。

## 标准条款冲突

架构 L0 §3 允许组件文件 PascalCase；前端 L0 §编码规范要求文件名英文 kebab-case。两者在 React 组件文件命名上冲突。为遵守前端专项基线，采用文件名 kebab-case、组件导出标识符 PascalCase；仅影响前端文件名，不改变类型、目录或后端 Python snake_case。当前批准依据为项目计划中的专项优先决策，若标准所有者要求不同，须在 P02 建项前重新审议。
