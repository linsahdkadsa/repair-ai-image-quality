# 通用前端设定（React 中台 / 管理后台，所有项目适用）

> 当项目包含 Web 管理台、运营后台或中台前端时，按本设定落地，并产出项目的 `FRONTEND_ARCHITECTURE.md` 作为 L0 强制基线；不允许擅自调整技术选型、目录、组件体系与设计 Token。
> 本设定与《通用架构设定》（后端/整体分层）配套：前端只负责交互展示，后端负责业务规则、权限、存储与任务执行；冲突时安全与正确性条款以更严格者为准。
> 技术线为 **Vite + React + TypeScript + Ant Design + ProComponents**；文中业务模块与路由均为示例，**实际模块以项目 SPEC 为准**。若团队已有等价且经评审的前端约束，可替换工具，但下文"能力与契约"（唯一组件体系、单一数据源、后端裁决权限、视觉回归、安全）不得缺失。

> **使用 Vite + React 的模块化单体前端，以 Ant Design + ProComponents 作为唯一组件体系；将"统一 Token、标准页面模板、Storybook、视觉回归"列为首期交付要求。技术栈保持克制，组件和交互规则保持严格，才能让中台在模块持续增加后仍然一致、可维护。**

# 一、总体架构决策

## 推荐方案

**Vite + React + TypeScript + Ant Design + ProComponents + React Router + SWR + Axios + CSS Modules + ECharts**

辅助能力：

- Zustand：按需管理跨组件 UI 状态。
- Storybook：维护共享组件及页面模板目录。
- Vitest + React Testing Library：单元与组件测试。
- Playwright：核心流程与视觉回归测试。
- OpenAPI：前后端接口契约。

## 核心架构原则

| 原则 | 具体要求 |
| - | - |
| 模块化单体 | 首期使用单个前端应用，按业务领域组织代码，不引入微前端 |
| 前后端分离 | 前端负责交互展示，后端负责业务规则、权限、存储和任务执行 |
| 一套组件体系 | Ant Design 为唯一基础组件库，ProComponents 承载中台业务组件 |
| 一套设计语言 | 页面共享 Token、布局模板、状态文案和交互规则 |
| 一份数据来源 | 服务端数据由 SWR 管理，不复制到多个状态容器 |
| 后端权限裁决 | 前端控制可见性，后端控制实际访问与操作 |
| 按需扩展 | AI 编辑器、流程编排、多租户等有明确需求后再引入 |

## 系统边界

```text
用户浏览器
    ▼
React 前端应用
    ├── 应用布局、路由与导航
    ├── 表格、表单、详情与分析
    ├── 调试与生成结果展示
    ├── 任务进度与调用日志
    └── 权限展示与交互反馈
    ▼
自有业务 API / 可选 BFF
    ├── 认证、权限、数据范围
    ├── 配置管理与审计
    ├── 上游服务代理与密钥管理
    ├── 文件上传与导出
    └── 异步任务与取消控制
    ▼
数据库 / 文件存储 / 上游服务 / 任务执行服务
```

已有后端能够提供上述能力时，不额外增加 BFF。确有接口聚合、协议转换等需求时再增加。

# 三、版本与运行环境约束

## 版本基线

项目启动时选择**已验证兼容的稳定版本组合**，不默认追逐最新大版本。验证顺序：

1. 选择仍处支持期的 Node.js LTS。
2. 核对 Vite 的 Node.js 要求。
3. 核对 React、Ant Design、ProComponents 的兼容声明。
4. 验证布局、表格、表单、弹窗、日期控件。
5. 验证 Storybook 和测试工具兼容性。
6. 锁定依赖版本并提交锁文件。

### 强制要求

- 不使用 beta、canary 作为生产默认版本。
- CI 使用 frozen lockfile 安装。
- 不使用强制安装掩盖依赖冲突。
- 大版本升级单独提交和验收。
- 本地与 CI 使用相同 Node.js、pnpm 版本。
- 版本清单必须记录选择依据和已知限制。

## 浏览器支持

默认支持企业实际使用的 Chrome、Edge 最近两个稳定版本。

- 存在 Safari 用户时纳入测试。
- 不支持 IE。
- 企业受管浏览器版本固定时，以实际版本确定构建目标。
- 明确最低支持视口，而不是只写"支持桌面端"。

## 环境划分

至少包含：本地开发、测试或预发布、生产。各环境隔离 API、认证配置和监控标识，禁止测试操作误连生产服务。

## 编码规范

- 文件名统一使用英文 kebab-case。
- React 组件使用 PascalCase。
- Hook 使用 `use` 前缀。
- 禁止无理由使用 `any`。
- 异步操作明确 loading、error 和终态。
- 组件渲染过程无副作用。
- 不在 `useEffect` 中自行搭建请求生命周期，使用 SWR 或已有数据层。
- 注释解释非显然的原因，不重复描述代码。

# 五、路由、导航与权限

## 路由组织

路由按业务领域组织，每条路由声明：

- 页面标题。
- 菜单名称和图标。
- 所需权限。
- 是否出现在菜单。
- 面包屑规则。
- 懒加载入口。

菜单与路由共享元数据，不维护两套相互独立的配置。详情页可以隐藏菜单项，但应正确高亮所属列表菜单。

## 权限模型

采用 **RBAC + 资源范围控制**。

| 权限层级 | 示例 | 权威执行位置 |
| - | - | - |
| 页面 | 查看某模块管理页 | 后端鉴权，前端辅助控制 |
| 操作 | 发布 / 执行某动作 | 后端操作鉴权 |
| 数据范围 | 查看所属范围数据 | 后端查询过滤 |
| 字段 | 查看敏感内容 | 后端脱敏或不返回 |

权限标识采用 `<resource>:<action>` 形式（如 `model:read`、`task:cancel`、`log:export`、`user:manage`），与后端权限码保持一致。前端通过统一权限工具（如 `PermissionGate` + `usePermission`）判断，不在页面散落角色字符串比较。

## 会话与权限生命周期

- 权限未加载完成前，不闪现受限内容。
- 未登录、无权限、资源不存在分别展示。
- 登出或账号切换时清理相应缓存与连接。
- 项目/范围切换时隔离查询缓存与数据范围。
- 服务端返回 403 时重新处理权限状态，而非只弹出错误。
- 后端返回资源标识，不返回可执行代码或任意组件路径。

# 六、数据请求与状态管理

## 状态归属

| 状态类型 | 归属 |
| - | - |
| 用户信息、权限、业务列表、任务详情 | SWR |
| 可分享的筛选、分页、排序 | URL Search Params |
| 表单字段与错误 | Ant Design Form |
| 弹窗开关、局部展开状态 | React 本地 state |
| 跨组件 UI 状态 | Zustand，按需 |
| 草稿、配置、版本、用户偏好 | 后端持久化 |

敏感搜索内容不直接写入 URL，避免出现在浏览历史、日志或分享链接中。

禁止：

- 把 SWR 数据再复制到 Zustand/Redux。
- 用 localStorage 存储业务数据或会话令牌。
- 将所有局部状态提升到全局。
- 同一页面出现两套独立的分页和筛选来源。

## 请求分层

```text
页面 / 组件
    ↓
模块查询 Hook（queries.ts）
    ↓
模块 API 函数（api.ts）
    ↓
统一 HTTP 客户端（shared/api，Axios 实例 + 拦截器）
    ↓
后端接口
```

Axios 负责传输与错误转换，SWR 负责缓存与重新验证，两者不重复管理同一职责。

## ProTable 数据规范

采用受控模式：

```text
URL 查询参数
    ↓
SWR 查询 Hook
    ↓
ProTable 的 dataSource / loading / pagination
```

- 不同时启用另一套 ProTable `request` 请求生命周期。
- query key 包含范围、筛选、排序和分页参数。
- 写操作成功后统一刷新受影响缓存（`mutate`）。
- 筛选改变通常回到第一页。
- 跨页选择必须显式设计，默认不隐式保留。
- 不为了通用性封装覆盖全部 ProTable API 的万能表格。

## 错误与重试

| 错误 | 处理原则 |
| - | - |
| 401 | 统一处理会话失效，保留安全的返回路径 |
| 403 | 显示权限不足，不进入重试循环 |
| 409 | 展示版本或状态冲突，允许重新获取 |
| 422 | 尽可能映射到字段错误 |
| 429 | 尊重 Retry-After，明确提示 |
| 5xx / 网络错误 | 查询可有限重试，提供手动重试 |

写操作，尤其发布、扣费、批量执行、启停，不做无条件自动重试。

## 数据契约

统一约定：分页/排序/过滤参数；错误码和字段错误结构；trace ID；时间格式与展示时区；金额精度及币种；空值语义；异步任务状态；导出方式与权限；并发控制与幂等机制。

# 七、设计系统与视觉规范

## 7.1 设计定位

- 浅色主题优先。
- 不使用营销式大标题和装饰性指标。
- 不使用无业务意义的渐变、图案和动效。
- 相同信息在不同页面使用相同表达。
- 通过布局、层级和留白区分内容，而非不断增加颜色。

## 7.2 唯一主题入口

```text
基础 Token → 语义 Token → Ant Design Theme / 图表主题 / CSS 变量 → 共享组件与页面模板 → 业务页面
```

根部统一使用：

- `ConfigProvider`：主题、中文 locale、组件默认配置。
- Ant Design `App`：提供能够继承上下文的消息、通知和弹窗能力。

业务代码通过项目约定的反馈入口调用，不随意使用绕过主题上下文的静态方法（如裸 `message.xxx`）。

## 7.3 Token 三层结构

| 层级 | 内容 |
| - | - |
| 基础 Token | 品牌色、字号、间距、圆角 |
| 语义 Token | 正文、次级文字、边框、背景、危险状态 |
| 组件 Token | 表格内边距、弹窗间距、菜单尺寸 |

业务页面消费语义 Token，不硬编码新的品牌色、阴影或圆角。CSS Modules 负责布局，不用于逐页重写 Ant Design 内部外观。

## 7.4 颜色基线

以五个基础色建立体系：

| 用途 | 基础色 |
| - | - |
| 品牌与主要操作 | 蓝色 `#1677FF` |
| 表面背景 | 白色 `#FFFFFF` |
| 文字与中性色阶 | 深灰 `#1F2329` |
| 成功 | 绿色 `#389E0D` |
| 错误与危险 | 红色 `#CF1322` |

补充规则：边框、次级文字、背景使用派生色阶；警告通过图标、文字和中性提示区域表达，不额外引入色系；状态必须包含文本，不能仅依靠颜色；图表复用主题，必要时通过线型、符号与分面区分；实测文字、交互状态和图表标记的对比度。

## 7.5 字体、间距与密度

| 项目 | 初始基线 |
| - | - |
| 正文 | 系统无衬线字体，14px |
| 行高 | 1.5 |
| 页面标题 | 24px，600 |
| 区块标题 | 16–18px，600 |
| 代码 | 等宽字体 |
| 间距 | 4、8、12、16、24、32px |
| 控件高度 | 默认 32px |
| 圆角 | 控件约 6px，容器约 8px |
| 顶部导航 | 约 56px |
| 侧栏 | 展开约 224px，折叠约 64px |
| 页面内边距 | 桌面 24px，窄屏 16px |

以上为待业务样板验证的初始值；字体不低于 14px，通过布局和间距提高密度，而不是不断缩小文字。

## 7.6 响应式与可访问性

- Flexbox 优先处理单维布局，Grid 用于复杂二维布局。
- 避免固定高度截断业务内容。
- 窄屏折叠菜单与筛选区域。
- 表格局部横向滚动，页面整体不溢出。
- 图标按钮提供可访问名称（`aria-label`）。
- 键盘可操作，焦点状态清晰；弹窗打开、关闭后正确管理焦点。
- 遵循减少动态效果的系统偏好（`prefers-reduced-motion`）。

## 7.7 视觉基线确认方法

先实现三个真实业务样板：高密度列表页、复杂配置表单、包含状态与操作的详情页；使用真实长度的字段和代表性数据验证，再冻结第一版 Token 与模板。

# 八、组件体系与页面模板

## 8.1 三层组件体系

| 层级 | 来源 | 使用规则 |
| - | - | - |
| 基础层 | Ant Design | 简单控件直接使用，通过主题统一 |
| 场景层 | ProComponents + 项目模板 | 高频复杂场景使用标准实现 |
| 领域层 | 项目业务组件 | 相同业务概念共享同一实现 |

不把每个基础组件重新包装一遍，也不允许每个页面自由拼装一套复杂交互。

## 8.2 首批共享能力

| 组件或能力 | 统一内容 |
| - | - |
| 页面容器 | 标题、说明、面包屑、主操作 |
| 筛选区域 | 字段排列、展开收起、查询与重置 |
| 编辑弹窗 / 抽屉 | 尺寸档位、提交、关闭、未保存提示 |
| `PermissionGate` | 权限展示 |
| `StatusTag` | 状态文案、颜色和图标 |
| `QueryState` | 加载、空数据、失败、重试 |
| `ConfirmAction` | 危险操作确认 |
| `CopyableText` | ID、请求编号复制 |
| `DateTimeText` | 时区与时间格式 |
| `JsonViewer` | 折叠、复制、脱敏提示 |
| `MarkdownViewer` | 安全渲染 |
| `TaskProgress` | 阶段、进度与终态 |
| 图表容器 | 标题、说明、加载、空状态、更新时间 |

优先复用 ProComponents 已提供的能力，仅封装项目特有约定。

## 8.3 标准页面模板

- **列表页**：标题+说明+主操作 → 筛选区域 → 已选数量+批量操作 → 数据表格 → 分页。
- **详情页**：标题+状态+主要操作 → 基本信息 → 标签页（配置/版本/记录/审计）。
- **配置页**：标题+当前版本 → 分组表单 → 校验与变更提示 → 保存/取消/发布。
- **分析页**：统一时间与业务筛选 → 关键指标趋势与分布 → 异常明细 → 更新时间与统计口径。
- **调试工作台**：目标选择 → 输入与参数配置 → 生成结果 → 执行状态、用量与错误。

模板统一结构和行为，不强行统一所有业务内容。

## 8.4 表格规则

- 默认一种全站密度；文本左对齐，数值与金额右对齐；数字使用等宽数字。
- 时间格式、空值占位统一；长文本截断后有完整查看入口。
- 常用操作直接展示，低频操作放入"更多"；操作顺序保持一致。
- 固定关键标识列和必要操作列，避免过多固定列。
- 表格筛选、分页、勾选行为形成统一规范。

## 8.5 表单与反馈规则

- 标签布局、字段宽度和分组方式统一；必填提示、校验触发时机一致。
- 短表单用弹窗，中等复杂度用抽屉，大型配置使用页面。
- 字段错误显示在字段旁；页面加载错误在页面内展示。
- 成功轻提示不遮挡后续操作；同一个错误只提示一次。
- 中文输入法组合输入（composition）期间，不触发 Enter 提交。

## 8.6 Storybook 与组件治理

每个共享组件至少记录：适用/不适用场景、默认状态和变体、加载/空/错误/禁用/无权限状态、长文案和窄容器表现、可访问性要求、使用示例和事件约定。

治理规则：新组件先检索已有组件；新页面先选择模板；修改共享组件须检查受影响场景；禁止页面随意覆盖 `.ant-*` 内部选择器；禁止无理由 `!important`；例外集中维护并记录原因；视觉变更通过截图差异审核。

# 九、流式与异步任务前端架构

## 9.1 流式接收

统一状态：`空闲 → 提交中 → 流式输出 → 完成 / 停止 / 失败`。

协议需明确：请求与会话标识、内容增量、运行阶段、用量信息、完成事件、错误事件、是否支持恢复与取消。

实现约束：

- 正确处理跨分块消息与 UTF-8 字符（缓冲半字符）。
- 使用 `AbortController` 取消读取；前端停止读取不等于后端停止执行。
- 不按每个字符重渲染整个页面（局部追加）。
- 用户查看历史内容时停止强制滚动。
- 不默认渲染原始 HTML（按 Markdown 安全渲染）。
- POST 流式使用 Fetch + ReadableStream；GET 订阅可用 EventSource；WebSocket 仅在确需双向实时通信时引入。

## 9.2 异步任务

批量处理、报表导出等采用：`提交 → 返回 taskId → 查询或订阅进度 → 获取结果`。

状态：`queued / running / succeeded / failed / canceling / canceled`。

- 后端是状态权威来源；进入终态后停止轮询；刷新后凭 taskId 恢复。
- 取消、重试依据权限和任务状态决定；前端不持有任务执行职责。
- 未知总量时展示阶段或不定进度，不伪造百分比。

## 9.3 配置版本

草稿与已发布版本分离；绑定明确版本；发布前展示影响范围；支持历史、差异和回滚；发布/回滚记审计；用版本号或 ETag 处理并发修改；需保留的草稿写入后端。

## 9.4 指标口径

统一定义：时区和统计窗口、维度（范围/应用/目标等）、重试/缓存命中/取消是否纳入、成功率分母、延迟分位（P95）、预估与实际口径、数据更新延迟；同一指标通过共享组件和统一后端口径展示。

# 十、安全与数据处理约束

## 10.1 认证与密钥

- 所有 `VITE_*` 变量按公开信息处理；浏览器不保存上游服务商密钥和数据库凭据。
- 优先同域部署和服务端会话；Cookie 使用 HttpOnly、Secure，SameSite 按拓扑配置；Cookie 写操作具备 CSRF 防护。
- 不在 localStorage 存储会话令牌；Web 凭证只保存在内存。

## 10.2 数据安全

- 权限与敏感字段过滤由后端执行；Markdown、URL、文件名均视为不可信输入；外链协议校验。
- 日志和监控默认脱敏；不记录完整凭据或未经批准的输入/输出内容。
- 文件类型、大小和访问权限由后端校验；敏感文件私有存储。
- 导出具有权限、数量限制和审计；CSV 导出处理公式注入（前缀 `'` 或 `="..."` 防护）。
- 审计由后端生成，前端不能作为唯一记录来源。

## 10.3 部署防护

网关配置真实响应头：`X-Content-Type-Options`、`Referrer-Policy`、HTTPS 下 HSTS、防点击劫持（X-Frame-Options/frame-ancestors）、Permissions-Policy，并逐步验证收紧 CSP。CSP 可先 Report-Only，切换到强制策略后才产生阻止效果。

# 十一、性能与稳定性

## 11.1 必需措施

- 页面级懒加载；Monaco、ECharts、高亮库按需加载；ECharts 仅注册所需能力。
- 大列表服务端分页；大日志使用游标查询。
- 避免不稳定的表格列定义与高成本重复计算（`useMemo`/`useCallback`）。
- 非必要轮询在后台标签页暂停；页面离开时清理连接和订阅。
- 主要路由提供错误边界；网络失败不清空用户输入。
- 不自动重试可能重复收费/发布/启停的操作。

## 11.2 建议性能基线

| 指标 | 建议目标 |
| - | - |
| LCP | P75 ≤ 2.5s |
| INP | P75 ≤ 200ms |
| CLS | P75 ≤ 0.1 |
| 列表分页 | 默认每页 20–50 条 |

目标需在固定设备、网络和数据规模下实测，前端渲染与后端延迟分别统计。

## 11.3 稳定性约束

空数据、旧缓存、超时、部分失败均有定义；前后端短期版本不一致可合理降级；实时连接断开显示状态、不伪装正常；高风险操作禁止未经确认的乐观成功；视觉占位与真实内容尺寸尽量一致。

# 十二、测试、CI 与部署

## 12.1 测试范围

| 类型 | 必测内容 |
| - | - |
| 单元测试 | 权限、参数转换、格式化、状态机 |
| 组件测试 | 筛选、分页、校验、确认、异常反馈 |
| E2E | 登录、权限、编辑发布、任务恢复、流式停止 |
| 视觉回归 | 页面模板、共享组件及关键状态 |

不以单一覆盖率百分比替代关键业务路径验证。

## 12.2 视觉回归规则

固定：浏览器版本、操作系统/容器、字体、视口、测试数据、时间和动画状态。优先覆盖：应用主框架；列表/详情/配置/分析模板；弹窗、抽屉；表格密度和长文本；加载/空/错误/无权限状态；关键窄屏视口。

## 12.3 CI 门禁

```text
frozen lockfile 安装
  → 类型检查(tsc) + ESLint + Stylelint + Prettier 检查
  → 单元与组件测试(Vitest/RTL)
  → 应用与 Storybook 构建
  → 关键 E2E + 视觉回归(Playwright)
  → 部署与冒烟
```

共享组件或主题变更时执行完整视觉回归；Vite 构建不代替 TypeScript 类型检查。

## 12.4 部署规范

- History 路由回退到 `index.html`；API 与不存在的静态资源不回退成 HTML。
- hash 资源长期缓存，入口 HTML 及时更新；构建时与运行时配置区分。
- Source Map 受控上传；监控关联发布版本；流式接口验证代理缓冲与超时。
- 前端可回滚，后端保留合理兼容窗口；内部 Storybook 访问权限独立配置，不默认公开。

# 十三、首期范围与暂不引入项

## 13.1 首期必须具备

- **工程基础**：版本和目录规范、应用布局/路由/菜单、真实身份与权限接入、请求/缓存/错误处理、环境/测试/CI/部署。
- **设计与组件基础**：统一主题 Token、Ant Design 全局配置、表格/表单/弹窗/反馈规范、列表/详情/配置模板、首批共享组件、Storybook 目录、视觉回归基线。
- **业务验证**：至少一个真实模块闭环（列表→详情→创建/编辑→权限限制→加载/空/失败状态→后端接口→自动化验收）。

## 13.2 首期不默认引入

微前端、完整多租户、低代码页面引擎、可视化工作流编排、多套组件库/状态库、任意换肤/复杂暗色、全页面保活与多标签、万能表单/万能表格、缺乏业务依据的多层抽象。

## 13.3 推荐启动顺序

确认业务目录与高频操作 → 锁定兼容版本与工程约束 → 建立 Token/布局/主题入口 → 完成真实列表/表单/详情样板 → 确认视觉基线 → 沉淀模板/组件/Storybook → 按模板扩展模块 → 持续交互测试与视觉回归。

# 十四、创建前必须确认的输入与页面完成标准

## 14.1 需求输入清单

业务目录、核心流程、用户与权限、身份体系、API 契约、流式/异步协议、数据口径、业务样本（真实长度字段与状态枚举）、视觉基线（品牌色/布局/密度）、运行环境（浏览器/域名/代理/超时）、合规要求（脱敏/日志/导出/审计/存储）、验收标准。

## 14.2 启动基线文档

技术选型与版本清单；工程目录与依赖规范；设计 Token 与视觉规范；组件目录与页面模板规范；接口、权限及流式协议契约；测试、部署与验收清单。

## 14.3 页面完成标准

一个页面只有同时满足以下条件才视为完成：使用标准模板与已批准组件；无未经定义的颜色/字号/间距/状态；接入真实接口；权限和异常状态完整；交互文案一致；长文本、窄屏和键盘操作可用；关键测试通过；视觉差异已审核；新增共享能力已补 Storybook；无敏感信息泄露和明显性能问题。
